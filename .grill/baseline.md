## 1. 一句话定义

**目标用户**：需要快速拿到初高中数学题的人（老师备课找题、学生自练、教育内容创作者）。
**核心问题**：手工出题耗时，找题库成本高，AI 生成质量参差且公式难渲染。
**一句话方案**：一个 Next.js 全栈网页，用户输入年级+知识点+难度+题型+题量，调用 DeepSeek 生成结构化数学题，前端用 KaTeX 渲染公式并支持一键复制。

## 2. 成功标准

| # | 标准 | 如何验证 | 达成时点 |
|---|---|---|---|
| S1 | DeepSeek 能按输入参数生成结构合法的初高中数学题（选择/填空），题干含 LaTeX 公式时 KaTeX 能正确渲染 | 本地跑通一次，取 10 道含公式题人工核对：题目对错 + 公式是否正常显示 | MVP 首次跑通 |
| S2 | 部署到 Vercel 后，浏览器访问 URL 能完成"输入参数→生成→展示+一键复制"全链路无报错 | Vercel 上访问 URL 跑一次完整流程，复制结果粘贴到记事本可读 | 部署后 |
| S3 | API key 全程不暴露在前端代码或网络响应中 | 浏览器 F12 查 Network 与源码，搜不到 key 明文 | 部署后 |

## 3. 范围

### 做什么（In Scope）

- [ ] 表单输入：年级（初一~高三 6 选 1）、知识点（文本输入）、难度（易/中/难）、题型（选择/填空）、题量（数字）
- [ ] 后端 route handler 接收参数 → 拼 prompt 调 DeepSeek → 返回结构化 JSON（题干/选项/答案，解析可选）
- [ ] 前端展示题目列表，KaTeX 渲染题干中的 LaTeX 公式
- [ ] 每题"一键复制"按钮（复制题干+选项+答案的纯文本）
- [ ] 后端代理藏 DeepSeek key（key 仅在 Vercel 环境变量）

### 明确不做什么（Out of Scope）

> 这一节往往比"做什么"更重要，是防止范围蔓延的边界。

- [ ] 不做账号登录 / 用户系统
- [ ] 不做历史记录保存（刷新即丢）
- [ ] 不做导出 Word/PDF
- [ ] 不做在线作答 / 自动批改 / 判分
- [ ] 不做语文/英语/物理/化学等其他学科
- [ ] 不做解答题 / 作文 / 阅读理解
- [ ] 不做后端数据库
- [ ] 不做题库管理 / 组卷

### 暂缓（Deferred，标记待定不阻塞当前版本）

- [ ] V2: 导出 Word/PDF
- [ ] V2: 在线作答 + 自动批改
- [ ] V2: 历史保存 / 账号体系（localStorage 或云端）
- [ ] V2: 扩学科（语数英起步）
- [ ] V2: 解答题 / 作文 / 阅读理解
- [ ] V2: 教材章节知识点树（替代自由文本输入）
- [ ] V2: 答案自验（用第二个 AI 调用核对答案）

## 4. 关键决策

| # | 决策 | 理由 | 可逆性 |
|---|---|---|---|
| D1 | 产品形态 = AI 自动出题平台（B） | 用户明确选择，AI 生成数学题，非组卷/刷题 | 难逆 |
| D2 | MVP 功能边界 = 仅展示 + 一键复制 | 先验证生成质量，导出/作答依赖生成稳定后才有意义 | 可逆 |
| D3 | 学科范围 = 数学单科 | 数学题型标准化、AI 生成质量最稳、易验证对错 | 可逆 |
| D4 | 年级范围 = 初一~高三全六学年 | 扩年级仅改 prompt 参数，成本极低 | 可逆 |
| D5 | 题型 = 选择题 + 填空题 | 标准化客观题，易生成、易自验答案；解答题步骤质量难保证 | 可逆 |
| D6 | AI 模型 = DeepSeek（V3/R1） | 数学推理强、性价比高、国内可直连、API 成熟 | 可逆 |
| D7 | API key 来源 = 用户自备，填后端环境变量 | key 不能裸放前端（F12 即可偷走），必须藏后端 | 难逆 |
| D8 | 历史保存 = 不存，刷新即丢 | MVP 聚焦生成质量，账号+DB 工程量跳一档放 V2 | 可逆 |
| D9 | 部署 = Vercel serverless 免费档 | 零运维、push 即上线、免费档够自用+小范围分享 | 可逆 |
| D10 | 前端栈 = Next.js (App Router) + TypeScript + Tailwind CSS | Vercel 原生支持，route handler 即 serverless 藏 key，TS 类型约束 AI 返回 JSON | 难逆 |
| D11 | UI 组件 = shadcn/ui | 轻、不锁包、Vercel 生态主流、风格简洁适合教育工具 | 可逆 |
| D12 | 数学公式渲染 = KaTeX | 数学题必有公式，DeepSeek 输出 LaTeX，KaTeX 渲染否则乱码；比 MathJax 轻快 | 可逆 |

## 5. 待验证假设

| ID | 假设 | 风险 | 验证方式 |
|---|---|---|---|
| A1 | DeepSeek 输出的 LaTeX 语法标准到能被 KaTeX 直接渲染 | high | 首次跑通时取 10 道含公式题用 KaTeX 渲染，全部正常显示即 verified；若出现渲染失败则 falsified，需加 LaTeX 清洗层（处理 \boldsymbol、\text 等非标准用法） |

## 6. 约束

- **技术约束**：Next.js App Router + TypeScript + Tailwind + shadcn/ui + KaTeX；Vercel serverless function；DeepSeek API；无数据库
- **时间/预算**：MVP 自用验证，DeepSeek API 按量付费（几块钱够测）；无固定预算上限
- **合规/政策**：初高中数学题内容合规不涉敏感；API key 不入 git 不上前端；题目内容仅用于学习场景

## 7. 已知风险

| # | 风险 | 影响 | 应对 |
|---|---|---|---|
| R1 | DeepSeek 偶尔输出非标准 LaTeX（如 \boldsymbol、\text{} 嵌套） | KaTeX 渲染失败，公式显示乱码 | 首次跑通验证 A1；证伪则加 LaTeX 清洗层 |
| R2 | DeepSeek 生成的题答案错误（数学题计算/推理错） | 题目不可用，误导学生 | MVP 一键复制让人工核对；V2 加答案自验（二次 AI 调用） |
| R3 | Vercel serverless function 超时（免费档 ~10s） | 长题量生成超时返回 500 | MVP 单次生成题量限制（≤5 题），UI 上限制题量输入 |
| R4 | API key 泄露 | DeepSeek 余额被盗 | key 仅在 Vercel 环境变量，不进 git（.gitignore .env），后端不返回 key 到前端 |

## 8. 被否掉的方案

| 方案 | 否决理由 |
|---|---|
| 老师出题工具（A 形态） | 工程量大、链路长（题库+组卷+分发+批改），适合教育机构长期投入，不适合"先做一个网页试试" |
| 学生刷题网站（C 形态） | 核心是"做题"不是"出题"，与用户描述偏离 |
| 纯前端静态页（无后端） | API key 必然暴露在前端，F12 即可偷走，安全不可接受 |
| GPT / Claude | 国内访问需代理，对国内初高中教材体系熟悉度不如国产模型 |
| MathJax | 比 KaTeX 更重更慢，Vercel 上体验差 |
| Ant Design / Element Plus | 风格偏中后台，不适合出题网页的教育工具气质 |
| MVP 含解答题 | 步骤生成质量难保证，且答案判定复杂，放 V2 |
| 语数英全学科 MVP | 单科聚焦更易快速验证，扩学科仅改 prompt，V2 再加 |

## 9. 交付物与第一个动作

**最终交付物**：一个可部署到 Vercel 的 Next.js 全栈应用，访问 URL 即可输入年级/知识点/难度/题型/题量，生成初高中数学题（选择/填空），KaTeX 渲染公式，支持一键复制。无账号、无持久化。

**第一个具体动作**：
1. `npx create-next-app@latest` 初始化项目（TypeScript + Tailwind + App Router）
2. 加 shadcn/ui（`npx shadcn-ui@latest init`）+ KaTeX（`npm i katex react-katex`）依赖
3. 建 `/api/generate` route handler 占位（先返回 mock JSON，验证前后端联通）
4. 前端建表单页（年级/知识点/难度/题型/题量 输入 + 生成按钮）
5. 接入 DeepSeek API（环境变量配 key，route handler 拼 prompt 调用）
6. 前端接真实响应 + KaTeX 渲染 + 一键复制
7. 部署 Vercel，验证 S1/S2/S3
